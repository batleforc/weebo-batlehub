1. Connect a BatleHub instance with an admin API token. The operator only
   reads a token from a Secret labelled for it:

     kubectl -n <namespace> create secret generic batlehub-admin --from-literal=token=<token>
     kubectl -n <namespace> label secret batlehub-admin batlehub.weebo.io/instance-token=true

     kubectl apply -n <namespace> -f - <<YAML
     apiVersion: batlehub.weebo.io/v1alpha1
     kind: BatleHubLocalInstance
     metadata:
       name: main
     spec:
       external:
         url: https://batlehub.example.com
         adminTokenSecretRef:
           name: batlehub-admin
           key: token
     YAML

   `kubectl get bhli` shows whether it answers (Ready, Reason).

2. With `spec.external.manageConfig: true` the operator pushes the
   configuration rendered from `spec.config`, `spec.configLayers` and the
   BatleHubRegistry objects it accepts (`kubectl get bhr`). A Secret whose
   content is sent to BatleHub must be labelled for it:

     kubectl -n <namespace> label secret <name> batlehub.weebo.io/credential=true

   Guide: https://batleforc.github.io/weebo-batlehub/docs/guides/manage-config

   A BatleHubNamespaceClaim (`kubectl get bhnc`) reserves a package prefix
   of a registry to a group:
   https://batleforc.github.io/weebo-batlehub/docs/guides/team-namespaces

   BatleHubPackageGrant and BatleHubPackagePolicy (`kubectl get bhpg,bhpp`)
   write the grants and policies of a package or a version:
   https://batleforc.github.io/weebo-batlehub/docs/guides/package-governance

   A BatleHubMaintenance (`kubectl get bhm`) runs an admin action, once or
   on a schedule: https://batleforc.github.io/weebo-batlehub/docs/guides/maintenance

3. Creating a BatleHubLocalInstance sends a Secret of its namespace to the
   URL it names: grant the kind like you grant pods.
