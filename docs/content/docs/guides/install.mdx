---
title: Install via Helm
description: Bring up the operator with its chart.
---

The chart lives at `oci://ghcr.io/batleforc/charts/weebo-batlehub`. It
needs [cert-manager](https://cert-manager.io) for the certificate of the
operator's HTTPS server (probes and admission webhooks).

```bash
helm install weebo-batlehub \
  oci://ghcr.io/batleforc/charts/weebo-batlehub \
  --namespace weebo-batlehub --create-namespace \
  --version <version>
```

The chart creates a self-signed issuer for that certificate. To use an
issuer of yours, add `--set certManager.createIssuer=false --set
certManager.issuerRef.name=<issuer>` (and `kind`, `ClusterIssuer` by
default).

Releases are alphas for now (`0.1.0-alpha.N`): Helm skips prereleases
unless the version is given (`--version`) or `--devel` is passed.

## Limited to one namespace

`--set watch.namespace=<namespace>` limits the operator to the instances
of that namespace: its kinds move from the ClusterRole to a Role there,
with every rule on namespaced resources — ConfigMaps and pods read, the
objects of managed instances (Deployments, Services, claims,
NetworkPolicies…), finished maintenances deleted: the operator can write
none of them elsewhere. BatleHub has no cluster-scoped kind; the operator
still reads and writes Secrets through its ClusterRole (`clusterSecrets`).
Registries of other namespaces are not seen, and no TokenReview binding
is made (see the managed instance guide).

`watch.clusterKinds: false` (no ClusterRole at all) works the same, on
the Role alone.

## Images of managed instances

A managed `BatleHubLocalInstance` runs only images whose repository is in
`managedInstances.allowedImages` (default `ghcr.io/batlehub/batlehub` and
`ghcr.io/batlehub/batlehub-worker`, env `WEEBO_BATLEHUB_ALLOWED_IMAGES`):
the webhook refuses another, and the operator applies nothing for it
(`InvalidSpec`). Add your mirror there:

```bash
helm upgrade weebo-batlehub oci://ghcr.io/batleforc/charts/weebo-batlehub \
  --reuse-values \
  --set 'managedInstances.allowedImages={registry.example.com/batlehub/batlehub,registry.example.com/batlehub/batlehub-worker}'
```

Creating a `BatleHubLocalInstance` still lets its author run BatleHub
with the Secrets of the namespace labelled
`batlehub.weebo.io/credential: "true"`: give the kind as you give pods.
